# 第一章：作用域（Scope）

## 1.1 概述

* `作用域` 决定了 `变量`、`函数` 等标识符的 `可访问范围`，即：决定了它们在哪里可以被使用。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-12/2026-11-12-17-57-49.png)

## 1.2 局部作用域（本地作用域）

### 1.2.1 概述

* `局部作用域` （Local Scope，本地作用域）由 `函数作用域` 和 `块级作用域` 组成。

### 1.2.2 函数作用域

* 在函数内部声明的变量只能在函数内部访问，外部无法直接访问。

> [!NOTE]
>
> * ① 函数的参数（形参）也是函数内部的局部变量。
> * ② 函数被调用时，将会形成局部作用域（栈帧）；一旦调用结束，局部作用域（栈帧）将会被销毁，其内部的变量等也随之销毁。
> * ③ 不同函数内部声明的变量无法互相访问。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>
  
  <script>
    /* 
      函数作用域：函数内部定义的变量，只能在函数内部访问
    */
    function test() {
      // ✅️ 函数内部定义的变量，只能在函数内部访问
      let localVar = "I am local" // [!code highlight]
      console.log(localVar)
    }
    
    test()

    // ❌️ 函数外部无法访问函数内部定义的变量
    // console.log(localVar) // [!code error]
  </script>
</body>
</html>
```

### 1.2.3 块级作用域

* 使用 `{}` 包裹的代码被称为代码块，代码块内声明的变量外部将 `有可能` 无法访问。

> [!NOTE]
>
> * ① let 关键字和 const 关键字声明的变量，都会产生块级作用域。
> * ② ~~var 关键字声明的变量不会产生块级作用域~~（不推荐使用）。
> * ③ 不同代码块之间的变量无法互相访问。
> * ④ 对象字面量没有产生块级作用域，如：`const obj = {...}` 。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>

<body>

  <script>
    /* 
      块级作用域：使用{}包裹起来的代码块，称为块级作用域
      块级作用域：在代码块内部定义的变量，只能在代码块内部访问
    */
    {
      let uname = "张三"
      // ✅️ 在代码块内部定义的变量，只能在代码块内部访问
      console.log(uname) // [!code highlight]
    }

    for (let i = 0; i < 5; i++) {
      // ✅️ 在代码块内部定义的变量，只能在代码块内部访问
      console.log('i', i) // [!code highlight]
    }


    // ❌️ 在 {} 外无法访问块级作用域内的变量
    // console.log(uname) // [!code error]
    // console.log(i) // [!code error]
  </script>
</body>

</html>
```

## 1.3 全局作用域

* `<script>` 标签和 `.js` 最外层的就是全局作用域，在此声明的变量等，在局部作用域内也可以访问。

> [!NOTE]
>
> * ① ~~为 window 对象动态添加的属性，默认是全局作用域~~（不推荐使用）。
> * ② ~~函数中未使用任何关键字声明的变量为全局变量~~（不推荐使用）。
> * ③ 尽可能少的声明全局变量，防止全局变量被污染。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>
  
  <script>
    /* 
      全局作用域：在代码的任意位置都可以访问的变量
    */
    let globalVar = 10

    function test() {
      // ✅️ 全局作用域：在函数内部也可以访问
      console.log(globalVar) // [!code highlight]
    }

    test()

    // ✅️ 全局作用域：在任意地方都可以访问
    console.log(globalVar) // [!code highlight]

  </script>
</body>
</html>
```

## 1.4 作用域链

* `作用域链` 本质上是 `变量的查找机制` 。

> [!NOTE]
>
> * ① 在执行执行的时候，会优先查看 `当前函数作用域` 中的局部变量。
> * ② 如果当前作用域中查找不到，则依次 `逐级查找父级作用域` 中的变量，直到全局作用域。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>

<body>

  <script>
    /* 
      作用域链：
        作用域链：是多个执行上下文的变量对象的层级链
        
        块级作用域 --> 函数作用域 --> 全局作用域
    */

    const x = 1 // 全局作用域

    function demo() { // 函数作用域
      const x = 2
      console.log('函数作用域：', x)

      if (true) { // 块级作用域
        let x = 3
        console.log('块级作用域：', x)
      }
      
      console.log('函数作用域：', x)
    }

    demo()

    console.log('全局作用域：', x)
  
  </script>

</body>

</html>
```

# 第二章：垃圾回收机制

## 2.1 概述

* JS 使用 `垃圾回收` 自动检测并回收不再使用的内存，帮我们释放资源，以避免内存泄漏。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-13/2026-11-13-08-26-17.png)

## 2.2 内存分配

### 2.2.1 数据类型

* 在 JavaScript 中，数据类型分为：`基本数据类型`（原始类型）和 `引用数据类型`（对象类型）。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-16-31-55.png)

### 2.2.2 内存分配

#### 2.2.2.1 概述

* JS 代码执行时，v8 等引擎会将内存分为 `栈` 和 `堆` ，如下所示：

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-16-37-10.png)

#### 2.2.2.2 栈

* `基本数据类型`、`函数调用` 和 `引用类型变量` 会在 `栈` 中进行 `执行` 或 `调用` 是 `后进先出`。

::: details 点我查看 具体细节

* ① 对于基本数据类型、函数调用以及引用类型变量在栈中，并不需要 GC（垃圾收集器）来进行管理，因为其调用完毕就直接被释放。
* ② 对于引用数据类型的对象是在堆中进行管理的，需要 GC（垃圾收集器）来进行管理，以防止造成内存泄漏。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-17-21-12.svg)

#### 2.2.2.3 堆

* `对象` 是在 `堆` 中进行维护的，而 `栈` 中保存 `该对象的引用`，并且该 `引用` 指向堆中的对象。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-21-39-36.svg)

## 2.3 判断对象是否可以回收

### 2.3.1 概述

* 判断对象是否可以回收，主要有两种方式：`引用计数法` 和 `可达性分析法`。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-21-44-22.png)

### 2.3.2 引用计数法

* 引用计数法，会为每个对象维护一个引用计数器，当对象被引用时加 1，取消引用时减 1。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-21-54-47.svg)

* 但是，引用计数法无法解决循环引用问题，即：A 引用 B，B 引用 A。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-15/2026-11-15-22-07-49.svg)

### 2.3.3 可达性分析法

* 从一组 `根(Root)` 开始查找，沿着引用关系查找仍然可以访问到的对象；无法从根访问到的对象，就是可以被回收的对象。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-10-32-31.png)

## 2.4 GC  算法

### 2.4.1 概述

* 基于 `可达性分析法` 的思想，判断对象是否可以回收，衍生出了多种 GC 算法，如：标记清除、标记复制、标记整理、分代收集和三色标记（增量/并发）。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-10-39-00.png)

### 2.4.2 标记 - 清除算法（Mark-Sweep）

* `标记-清除算法` 是最基础的算法，分为标记和清除两个阶段，即：先标记所有从根节点可达的存活对象，然后统一回收所有未被标记的对象。

::: details 点我查看 具体细节

* ① 标记 - 清除算法的优缺点，如下所示：

| 优缺点     | 描述                                                         |
| ---------- | ------------------------------------------------------------ |
| :one: 优点 | 实现简单，不需要移动对象，在不移动对象的前提下回收内存。     |
| :two: 缺点 | 会产生内存碎片。                                             |
| ^^         | 回收后，存活对象在内存中分散分布，可能导致后续无法为大对象分配连续空间，从而提前触发 GC。同时，标记和清除过程的效率不算高。 |

* ② 适用场景：常作为老年代的基础算法之一，或与其他算法结合使用。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-10-43-54.png)

### 2.4.3 标记 - 复制算法 (Mark-Copying)

* 可用内存分为大小相等的两块，每次只使用其中一块。GC 时，将正在使用的块中的存活对象 `复制` 到另一块空闲块中，然后一次性清空原块。

::: details 点我查看 具体细节

* ① 标记 - 复制算法的优缺点，如下所示：

| 优缺点     | 描述                                                         |
| ---------- | ------------------------------------------------------------ |
| :one: 优点 | 没有内存碎片，分配内存时只需移动堆顶指针，实现简单高效。     |
| :two: 缺点 | 内存利用率低，始终有一半空间是空闲的。                       |
| ^^         | 其效率与存活对象数量负相关，如果存活对象很多，复制开销会变得很大。 |

* ② 适用场景：非常适合对象“朝生夕死”的 **新生代**（Young Generation）。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-10-50-45.png)

### 2.4.4 标记 - 整理算法（Mark-Compact）

* `标记-整理算法` 是 `标记-清除算法` 的改进版，即：在标记完存活对象后，将所有存活对象都向内存的一端移动，然后直接清理掉边界以外的内存。

::: details 点我查看 具体细节

* ① 标记 - 整理算法的优缺点，如下所示：

| 优缺点     | 描述                                                         |
| ---------- | ------------------------------------------------------------ |
| :one: 优点 | 解决了内存碎片问题，同时避免了复制算法的空间浪费。           |
| :two: 缺点 | 效率较低，因为需要移动存活对象并更新所有指向它们的引用，这是一个成本很高的操作。 |

* ② 适用场景：适用于对象存活率高的 **老年代**（Old Generation）。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-10-51-59.png)

### 2.4.5 分代收集算法 (Generational Collection)

* 这并非一种独立的回收算法，而是一种 `策略框架`，即：它基于“弱分代假说”（大多数对象都是朝生夕灭的），将堆内存划分为 `新生代` 和 `老年代`。

::: details 点我查看 具体细节

* ① 新生代：对象存活率低，适合采用 **复制算法**，能以较小代价回收大量垃圾。
* ② 老年代：对象存活率高，没有多少垃圾可回收，适合采用 **标记 - 清除** 或 **标记 - 整理** 算法。

* ② 优点：**因地制宜，综合效率高**，是现代商业 JVM（HotSpot）垃圾回收器的基石。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-11-00-26.png)

### 2.4.6 三色标记法

* 为了解决传统 GC 在标记阶段需要长时间暂停应用（Stop-the-World）的问题，引入了增量式或并发式收集，其核心实现技术是 `三色标记法`。

::: details 点我查看 具体细节

* ① 三色标记法的核心，即：将对象标记为三种颜色：

| 对象的颜色   | 描述                                             |
| ------------ | ------------------------------------------------ |
| :one: 白色   | 未被 GC 访问过的对象。                           |
| :two: 灰色   | 自身已被访问，但其引用的其他对象尚未被完全扫描。 |
| :three: 黑色 | 自身及其所有引用对象都已被扫描过。               |

* ② 优点：GC 线程可以与用户线程“并发”地、以“增量”方式逐步推进标记过程，将长时间的暂停分解成许多短暂的停顿，从而 **极大地降低了 GC 的停顿时间**，适用于对实时性要求高的系统。

:::

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-16/2026-11-16-11-04-13.png)

# 第四章：函数进阶

## 4.1 函数提升

* JavaScript 在代码执行前，会将函数声明提升到当前作用域的顶部，使其可以在声明之前调用。

```html [index.html]
    /* 
      函数提升：
        函数声明提升到当前作用域的顶部，函数表达式和箭头函数不会提升
    */

    function foo() {
      console.log('foo')
    }

  </script>
```

## 4.2 函数参数

### 4.2.1 概述

* 函数的参数，可以让函数处理不同的数据，提高代码复用性，使其调用时更灵活。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-13/2026-11-13-14-40-12.png)

### 4.2.2 动态参数（了解）

* 格式：

```js
function 函数名(形参1,形参2,...){
    // arguments
}

函数名(实参1,实参2,...)
```

> [!NOTE]
>
> * ① 在函数内部有一个特殊的对象，即：arguments 对象，其是一个伪数组（不是真正的数据，无法使用 forEach() 等方法）。
> * ② 默认情况下，`arguments` 对象是 `所有（非箭头）函数` 中都可以使用的 `局部变量`，即：`arguments`  只存在于 function 定义的函数中。
> * ③ arguments 对象是 ES5 之前的写法，在 ES6 之后，推荐使用 `剩余参数` 来代替 arguments 对象了。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>

<body>

  <script>

    function foo() {
      // 判断 arguments 是否为对象
      console.log(typeof arguments) // object
      // 判断 arguments 是否为数组
      console.log(Array.isArray(arguments)) // false
      // 遍历 arguments 对象
      for (let i = 0; i < arguments.length; i++) {
        console.log(arguments[i])
      }
    }

    foo(10, 20, 30)
    console.log('-----------------')
    foo(10, 20, 30, 40)

  </script>

</body>

</html>
```

```md:img [cmd 控制台]
![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-01/2026-11-01-23-08-46.gif)
```

:::

### 4.2.3 默认参数

* 格式：

```js
function 函数名(形参1,形参2 = 值){
    // arguments
}

函数名(实参1,实参2,...)
```

> [!NOTE]
>
> * ① 当形参对应的实参 `缺少` 或为 `undefined` 的时候，默认参数（default parameter）生效。
> * ② 当形参对应的实参为 `null` ，默认参数并不会生效。 



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>

<body>

  <script>
    /* 
      默认参数，即：形参的默认值
    */
    function foo(name = "同学") {
      console.log(`你好，${name}！`)
    }

    foo() // 你好，同学！
    foo('小明') // 你好，小明！
    foo(undefined) // 你好，同学！
    foo(null) // 你好，null！

  </script>

</body>

</html>
```

### 4.2.4 剩余参数（其余参数）

* 格式：

```js
// ... parameters 就是剩余参数（其余参数）
function 函数名(形参1,形参2, ... parameters){
    // arguments
}

函数名(实参1,实参2,...)
```

> [!NOTE]
>
> * ① 当参数数量不确定的时候，可以使用 `...` 将剩余实参收集为数组，其就是为了替代 arguments 对象。
> * ② 如果有多个参数，那么剩余参数必须放到形参列表的最后一个位置。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>

  <script>

    /* 
      rest参数，即：剩余参数 
    */
    function sum(...numbers) {
      // 判断剩余参数是否为数组
      console.log(Array.isArray(numbers))

      for (let number of numbers) {
        total += number;
      }

      return total;
    }

    console.log(sum(10, 20, 30, 40)) // 100
```

## 4.3 箭头函数

### 4.3.1 概述

* `箭头函数` 是 ES6 新增的函数写法，使用 `=>` 表示，写法更简洁，常常用于回调函数。

![](https://github-pic.oss-cn-hangzhou.aliyuncs.com/web/2026-11-13/2026-11-13-14-35-46.png)

### 4.3.2 语法

* 格式：

```js
const 函数名 = (参数列表) => {
  // 函数体
  return 返回值;
}
```

> [!NOTE]
>
> * ① 普通函数 VS 箭头函数 VS 箭头函数简写，如下所示：
>
> ```js
> // 普通函数（函数表达式）
> const add = function (a, b) {
>   return a + b
> }
> 
> // 箭头函数
> const add = (a, b) => {
>   return a + b
> }
> 
> // 箭头函数简写
> const add = (a, b) => a + b
> ```
>
> * ② 箭头函数的语法细节，如下所示：
>
> | 箭头函数的组成  | 描述                               |
> | --------------- | ---------------------------------- |
> | :one: `()`      | 声明形参列表                       |
> | :two: `=>`      | 箭头符号，连接参数列表和函数体     |
> | :three: `{}`    | 函数体                             |
> | :four: `return` | 返回函数执行结果，可以根据条件省略 |
>
> * ③ `箭头函数` 也可以被称为 `Lambda 表达式`，并且箭头函数中没有 this，只会从自己的作用域链的上一层沿用 this。
> * ④ `箭头函数` 更适用于哪些本来需要 `匿名函数` 的地方。



* 示例：

::: code-group

```html [index.html]
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>
  
  <button class="btn">点我</button>

  <script>
    /* 获取元素 */
    const btn = document.querySelector('.btn');
    /* 添加事件监听 */
    btn.addEventListener('click', () => {
      alert('按钮被点击了！')
    })
  </script>
</body>
</html>
```

### 4.3.3 简写规则

* 剪头函数的简写规则，如下所示：

::: details 点我查看 具体细节

* ① 箭头函数属于表达式函数，因此没有函数提升。 
* ② 箭头函数如果只有一个参数，可以省略小括号。
* ② 函数体只有一行代码时，可以省略大括号和  `return`。
* ③ 返回对象字面量时，需要用小括号包裹对象。

:::

| 情况       | 完整写法                            | 简写规则                       |
| ---------- | ----------------------------------- | ------------------------------ |
| 无参数     | `() => {}`                          | `()` 不能省略                  |
| 一个参数   | `(x) => {}`                         | 可以省略 `()`                  |
| 多个参数   | `(a, b) => {}`                      | `()` 不能省略                  |
| 单个表达式 | `(a, b) => { return a + b; }`       | 可以省略 `{}` 和 `return`      |
| 返回对象   | `() => { return { name: 'Tom' }; }` | 使用 `() => ({ name: 'Tom' })` |
| 多条语句   | `() => { fn1(); fn2(); }`           | 必须保留 `{}`                  |
